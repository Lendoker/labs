# Лабораторні роботи з алгоритмів (1-23)

Інтерактивний веб-проєкт для вивчення алгоритмів сортування та пошуку, а також
базових структур даних: хеш-таблиць, зв'язних списків, стеків, черг, дерев і графів.
Кожна лабораторна має теоретичний блок, псевдокод/код, візуалізацію та метрики виконання.

## Що реалізовано

### Для сортувань і пошуку (ЛР1-10)

- покрокове проходження алгоритму (`Крок`) і автоматичне програвання (`Авто-режим`);
- регулювання швидкості анімації через слайдер та числове поле;
- генерація випадкових масивів (у т.ч. з розширеними опціями);
- аналітика: порівняння, перестановки/ітерації, позиція знайденого елемента, час;
- кольорова візуалізація станів елементів (активний, відсортований, знайдений, тощо);
- звукові ефекти кроків та завершення.

### Для хеш-таблиць (ЛР11-12)

- інтерактивна вставка/пошук/видалення через текстове меню;
- візуалізація bucket-ланцюжків і слотів відкритої адресації;
- статистика колізій, максимального ланцюжка, заповнення;
- порівняння хеш-функцій (`sum`, `djb2`, `polynomial`) та двох методів вирішення колізій.

### Для зв'язних списків, стеків і черг (ЛР13-17)

- однозв'язний, двозв'язний і кільцевий списки з візуалізацією вузлів та стрілок;
- стек і черга на масиві та на списку (поряд у двох панелях);
- кільцева черга, пріоритетна черга та дек з підсвіткою `front/rear/head/top`;
- журнал операцій з таймстемпами, підсвітка активного вузла, миттєва аналітика (`length`, `min`, `max`, `sum`, `avg`, `collisions` тощо).

### Для дерев (ЛР18-20)

- бінарне дерево пошуку з обходами `InOrder`, `PreOrder`, `PostOrder` та операціями `Insert`, `Search`, `Delete`;
- AVL-дерево з автоматичним балансуванням, підсвіткою висоти/балансу вузлів та журналом обертів (LL/RR/LR/RL);
- префіксне дерево (Trie) для рядків з пошуком за словом, префіксом і видаленням;
- SVG-візуалізація з in-order розкладкою для дерев і DFS-розкладкою для Trie.

### Для графів (ЛР21-23)

- введення графа матрицею суміжності з клавіатури або списком ребер (`a-b` чи `a-b:вага`);
- автоматична довідка про граф: тип (орієнтований/неорієнтований), вага, петлі, кількість ребер, степені вершин, список суміжності, зв’язність;
- покрокова візуалізація DFS і BFS з підсвіткою поточного ребра, відвіданих вершин, порядку обходу;
- для BFS — додаткова панель стану черги (`front`/`rear`), для DFS — індикація tree-edge / back-edge / backtrack.

### Спільні можливості

- світла/темна тема;
- адаптивний дизайн з боковою панеллю навігації та мобільним меню;
- URL-роутинг (`/labN`) для прямих посилань на конкретну лабораторну.

## Перелік лабораторних

### Сортування

1. **ЛР1 — Selection Sort**  
   Ідея: на кожній ітерації обирається мінімальний елемент з невідсортованої частини.  
   Складність: `O(n^2)`.

2. **ЛР2 — Insertion Sort**  
   Ідея: елемент вставляється на правильну позицію у вже відсортованому префіксі.  
   Складність: найкраща `O(n)`, середня/гірша `O(n^2)`.

3. **ЛР3 — Bubble Sort**  
   Ідея: сусідні елементи порівнюються та міняються місцями.  
   Складність: найкраща `O(n)`, середня/гірша `O(n^2)`.

4. **ЛР4 — Merge Sort**  
   Ідея: підхід "розділяй і володарюй" з подальшим злиттям підмасивів.  
   Складність: `O(n log n)`.

5. **ЛР5 — Quick Sort**  
   Ідея: розбиття масиву відносно опорного елемента (`pivot`).  
   Складність: середня `O(n log n)`, найгірша `O(n^2)`.

6. **ЛР6 — Shell Sort**  
   Ідея: insertion-sort із поступовим зменшенням кроку (`gap`).  
   Складність: залежить від послідовності `gap`.

7. **ЛР7 — Cocktail Shaker Sort**  
   Ідея: двонапрямлений прохід (зліва направо і справа наліво).  
   Складність: найкраща `O(n)`, середня/гірша `O(n^2)`.

8. **ЛР8 — Heap Sort**  
   Ідея: побудова `max-heap` і послідовне вилучення максимуму.  
   Складність: `O(n log n)`.

### Пошук

9. **ЛР9 — Лінійний пошук + лінійний пошук з бар'єром**  
   Два варіанти пошуку: класичний та sentinel-підхід.  
   Складність: `O(n)`.

10. **ЛР10 — Двійковий пошук**  
    Пошук у відсортованому масиві (в UI масив сортується перед пошуком).  
    Складність: `O(log n)`.

### Хешування

11. **ЛР11 — `hashMapTable`**  
    Методи:
    - `Insert(key, value)`
    - `SearchKey(key)`
    - `Remove(key)`

    Додатково:
    - separate chaining для обробки колізій;
    - візуалізація bucket-ланцюжків;
    - статистика (`size`, `capacity`, `load factor`, `collisions`, `max chain`, `resizes`);
    - порівняння хеш-функцій (`sum`, `djb2`, `polynomial`);
    - автоматичне розширення таблиці.

12. **ЛР12 — Вирішення колізій у хеш-таблицях**  
    Дві стратегії поряд:
    - відкрита адресація з квадратичним пробуванням: `index = (h + attempt²) % SIZE`;
    - метод ланцюжків (separate chaining).

    Хеш-функція — мультиплікативна (`A ≈ 0.618033`).  
    Аналітика: `open used`, `open collisions`, `chain used`, `chain collisions`, `max chain`.

### Зв'язні списки

13. **ЛР13 — Однозв'язний список**  
    Операції: `InsertHead`, `InsertTail`, `Remove`, `Search`, `Reverse`, `Count`, `Display`.  
    Візуалізація: вузли-картки зі стрілками `next` і підсвіткою активного вузла.

14. **ЛР14 — Двозв'язні та кільцеві списки**  
    - `DoublyLinkedList` з `InsertFront/InsertBack`, `DeleteFirst/DeleteLast`, `Search`, вивід у прямому та зворотньому напрямку;
    - `CircularList` з `InsertCircularBack`, `Remove` і круговим рендером вузлів.

### Стеки та черги

15. **ЛР15 — Реалізація стеків**  
    Дві реалізації поряд:
    - `ArrayStack` (масив фіксованого розміру, `MAX_SIZE = 8`);
    - `ListStack` (на однозв'язному списку, вершина = голова).

    Операції: `push`, `pop`, `peek`, `isEmpty`, `isFull`, `search`, `sum`, `average`, збереження/завантаження.

16. **ЛР16 — Реалізація черг**  
    Три реалізації:
    - `ArrayQueue` — лінійна з `front/rear`;
    - `CircularArrayQueue` — кільцева на масиві з повторним використанням слотів;
    - `ListQueue` — на однозв'язному списку з двома вказівниками (`front`, `rear`).

    Операції: `enqueue`, `dequeue`, `peek`, `min`, `max`.

17. **ЛР17 — Черга з пріоритетами та дек**  
    - `PriorityQueue` на однозв'язному списку, список впорядкований за спаданням пріоритету (операції `pushPriority`, `popPriority`, `top`);
    - `Deque` (двобічна черга) з операціями `pushFront`, `pushBack`, `popFront`, `popBack`.

### Дерева

18. **ЛР18 — Реалізація дерев (BST)**  
    - бінарне дерево пошуку з операціями `Insert`, `Search`, `Delete`;
    - три обходи: `InOrder` (відсортована послідовність), `PreOrder`, `PostOrder`;
    - аналітика: кількість вузлів, висота, мінімум, максимум.

19. **ЛР19 — AVL-дерева та їх балансування**  
    - самобалансоване BST: висота піддерев і коефіцієнт балансування зберігаються у вузлах;
    - усі чотири випадки балансування (LL, RR, LR, RL) з журналом обертів;
    - демо «1..10» демонструє, як AVL утримує висоту `O(log n)` навіть у виродженому випадку.

20. **ЛР20 — Trie (префіксне дерево)**  
    - словник латинських слів зі вставкою, пошуком слова, пошуком за префіксом, видаленням;
    - кожне ребро підписане символом, кінці слів виділені зеленим;
    - окремі панелі: усі слова словника та слова з останнім введеним префіксом.

### Графи

21. **ЛР21 — Представлення графів**  
    - матриця суміжності з клавіатури або список ребер (підтримка ваг і прапорця «орієнтований»);
    - довідка: тип графа, наявність петель, кількість ребер, степені вершин (`deg` / `in` + `out`), список суміжності, зв’язність неорієнтованого графа;
    - круговий рендер графа у SVG з ваговими підписами.

22. **ЛР22 — Пошук у глибину (DFS)**  
    - покрокова рекурсивна реалізація з підсвіткою поточної вершини, активного ребра, повернень з гілок;
    - автоматичне розширення на нову компоненту зв’язності, якщо граф не зв’язний;
    - регулювання швидкості, режим «Крок»/«Авто»/«Скинути», лічильник відвіданих вершин.

23. **ЛР23 — Пошук у ширину (BFS)**  
    - обхід на основі черги з окремою візуалізацією її стану (`front` / `rear`);
    - події `start`, `dequeue`, `enqueue`, `edge-skip`, `component`, `done`;
    - індикатор кроку, лічильник елементів у черзі, перевірка зв’язності.

## Швидкий старт

### Вимоги

- Node.js 18+ (рекомендовано LTS)
- npm 9+

### Встановлення залежностей

```bash
npm install
```

### Режим розробки

```bash
npm run dev
```

Після запуску відкрийте адресу, яку покаже Vite у консолі (зазвичай `http://localhost:5173`).

### Production build

```bash
npm run build
```

### Локальний preview зібраного проєкту

```bash
npm run preview
```

### Запуск через `server.js` (наприклад для Render)

```bash
npm run start
```

Сервер очікує, що вже існує папка `dist/` (тобто попередньо виконано `npm run build`).
За замовчуванням порт: `10000`, але може бути перевизначений змінною `PORT`.

## Як користуватись інтерфейсом

1. Виберіть лабораторну у бічному меню.
2. **Для сортувань/пошуку (ЛР1-10):**
   - введіть масив вручну або згенеруйте випадковий;
   - для пошуку вкажіть цільове значення;
   - запустіть алгоритм (`Сортувати` / `Лінійний` / `З бар'єром` тощо);
   - використовуйте `Крок` для покрокового проходження або `Авто` для неперервної анімації;
   - регулюйте темп слайдером швидкості.
3. **Для хеш-таблиць (ЛР11-12):**
   - оберіть команду (`Insert`/`Search`/`Remove`);
   - введіть ключ (і значення для Insert);
   - спостерігайте за зміною стану таблиці, колізіями та порівнюйте хеш-функції.
4. **Для зв'язних списків, стеків, черг (ЛР13-17):**
   - оберіть команду з меню (напр. `Push`, `Pop`, `Enqueue`, `InsertHead`, `pushPriority`);
   - введіть значення (і пріоритет, де потрібно);
   - натисніть `Виконати` — візуалізація та журнал оновляться одразу.
5. **Для дерев (ЛР18-20):**
   - оберіть команду (`Insert`, `Search`, `Delete`, `Traverse`, `Prefix`);
   - введіть значення (для Trie — латинське слово);
   - дерево перемалюється у SVG, активний шлях/останній вузол підсвітяться.
6. **Для графів (ЛР21-23):**
   - заповніть матрицю суміжності або список ребер та натисніть `Застосувати`;
   - для обходів — оберіть стартову вершину і використовуйте `Крок`/`Авто` для покрокового програвання;
   - спостерігайте за зміною кольору вершин і станом черги (для BFS) або порядком стека (для DFS).
7. Звіряйтеся з блоком аналітики під кожною структурою.

## Метрики та інтерпретація

- **Порівняння**: кількість логічних порівнянь елементів/ключів;
- **Перестановки**: кількість обмінів елементів (для сортувань);
- **Індекс**: позиція знайденого елемента (для пошуку);
- **Час (мс)**: технічний час виконання алгоритму в JS (орієнтовна величина).

> Важливо: на малих масивах час може коливатись через оверхед браузера та рендеру.

## Додавання нової лабораторної (чекліст)

1. Створити алгоритм у `src/core/algorithms`.
2. Повертати уніфікований результат (включно з `steps` та метриками).
3. Додати сторінку у `src/ui/components` (наприклад, `Lab12Page.js`).
4. Підключити сторінку у маршрути/навігацію (`App.js`, `Sidebar.js`).
5. Додати опис у цей README.

## Типові проблеми

- **`npm run start` показує порожню сторінку / 404**  
  Виконайте `npm run build` перед запуском `start`.

- **Порт зайнятий**  
  Для dev-режиму Vite автоматично запропонує інший порт.  
  Для `start` задайте змінну `PORT`.

- **Некоректне введення масиву**  
  Переконайтеся, що введені лише числа з коректними роздільниками.
